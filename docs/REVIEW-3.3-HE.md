# Workout 3.3 — סקירת מוצר ותיקונים

12 בספטמבר 2026. נבדקו קוד המקור של שתי האפליקציות, תיעוד הבניות הקודמות, מנוע האימון, אחסון, תיאום פעולות, שירותי Android והמסכים. השינויים נעשו רק ב־Workout-Rebuilt.

## מה נשמר ולמה

למימוש החדש יש בסיס טוב: סטים בודדים עם ערכים בפועל, שמירה אטומית ב־DataStore, היסטוריה שאינה תלויה באיפוס שבועי ו־WorkoutCoordinator משותף למסכים ולהתראות. לא היה צורך להחליף שוב את הארכיטקטורה. נשמרו מסך האימון הישיר עם ימי השבוע, הכרטיסים, סימוני ההתקדמות, מאגר 41 התרגילים והאייקון המקורי.

המראה הבהיר והכרטיסים בעלי הגבול העדין מתאימים לשימוש בזמן אימון. לפי בקשתך נוסף גם ניסוי לבחירה בהשראת Liquid Glass: רקע מדורג, שקיפות מתונה, שוליים מוארים וצל עדין. המספרים והכפתורים נשארים אטומים. אין טשטוש חי או אנימציה מתמדת; אלו משטחים ב־Compose שנבדקים בתוך אפליקציית Android עצמה.

## כללי התוכנית לאחר התיקון

- כל אימון יכול לשלב כל קבוצת שרירים ותרגילים. ABC היא תבנית התחלה בלבד.
- הרצף הגמיש ממשיך בין שבועות. תאריך תחילת השבוע אינו משנה את הסבב.
- פתיחה או צפייה אינן מתחילות אימון. הסט הראשון פותח את האימון, ואם הסבב הקודם מלא — גם סבב חדש.
- ביטול כל הסטים מבטל את אותה התחלה. השלמה פעילה ניתנת לביטול עד סיום ושמירה.
- אימון חלקי נשמר בהיסטוריה ואינו משלים את האימון בסבב. חזרה על אימון שכבר הושלם אינה משלימה אימון אחר.
- שינוי שם או סדר שומר על הזהות וההתקדמות. אימון חדש מצטרף לרשימת הנותרים; אימון שהוסר אינו נדרש עוד. הסבב של אימון שכבר התחיל נשאר קבוע.
- מעבר בין מצב גמיש לקבוע אינו משנה בדיעבד את משמעות האימון הפעיל. כל אימון שומר את המצב שבו התחיל.
- בימים קבועים כל תאריך הוא מופע נפרד, גם אם אותו אימון משובץ פעמיים.
- מחיקת רשומה מההיסטוריה מסירה אותה מהיומן אך שומרת על ההתקדמות השמורה בסבב, כפי שמוסבר בדיאלוג הקיים.
- לפי החלטתך, סיום ידני הוא ברירת המחדל, גם בקריאת נתוני 3.2. האימון נשאר פתוח עד שתבחר לסיים ולשמור. אפשר להפעיל סגירה לאחר חוסר פעילות בהגדרות הטיימר; גם אז מנוחה פעילה או מושהית מוגנת.

## ניסוי Liquid Glass

בהגדרות ← מראה ושפה ← גימור הכרטיסים אפשר לבחור בין ״נקי״ ל״זכוכית עדינה״. המראה הנקי נשאר ברירת המחדל כדי לאפשר השוואה; הניסוי אינו משנה את הניווט או את מנוע האימון. צילום `home-he.png` מציג את המראה הנקי ו־`home-glass-he.png` מציג את הזכוכית עם אותם נתוני אימון. הכיוון מתאים בעיניי במינון הזה, בתנאי שהמשתמש מעדיף את הרקע הצבעוני מעט יותר.

## כיסוי מול המקור

| יכולת | מצב |
|---|---|
| לוגו ואייקון, כרטיסים, מדדי סטים והשלמה | נשמרו |
| מאגר 41 תרגילים, חיפוש, תרגילים אישיים, סדר והערות | נשמרו |
| משקל, יעדי חזרות וטווחי יעד, שניות ודקות | נשמרו; תיקון משקל של סט בודד נוסף |
| מנוחה ברקע, התראה, השהיה, המשך, שינוי משך ופעולות | נשמרו ותוקנו מקרי הקצה המפורטים לעיל |
| תזכורות לפי ימים, שעה והודעה אישית | נשמרו; בקשת ההרשאה מוצגת בהקשר של יצירת תזכורת |
| ביצוע קודם והיסטוריה מלאה/חלקית | נשמרו עם ערכים ומשקלים לכל סט |
| עברית, אנגלית, שפת מכשיר; בהיר, כהה ומערכת | נשמרו; בחירת שפה זמינה גם לפני יצירת התוכנית |
| תוכנית עם אימונים עצמאיים ורצף בין שבועות | קיימת בחדש; המקור היה מבוסס על אימוני ימים |
| גיבוי ושחזור JSON | קיים בחדש; אינו מייבא נתוני v2 אוטומטית |
| איפוס סימונים שבועי ופתיחת יום אוטומטית של המקור | הוחלפו בסיכום שבועי שאינו מוחק נתונים ובהצעה לאימון הבא |

היסטוריה עדיין נשמרת כחלק ממסמך DataStore אחד. זו בחירה סבירה להיקף הנוכחי; אלפי רשומות לאורך שנים לא נבדקו כאן. מעבר ל־Room מוצדק אם מדידה של נתונים גדולים תראה צורך.

## תאימות ומגבלות

השדות החדשים ניתנים לקריאה עם ברירות מחדל, ללא איפוס נתוני 3.2. לא השתנו application ID או הגדרת החתימה. נתוני הדגמה וצילומים נוצרים באמולטור מתוך קוד בדיקות בלבד, ואינם נכללים ב־APK להתקנה.

בדיקות אמולטור אינן אישור לאמינות במכשיר פיזי. טרם נבדקו כאן ניהול סוללה של יצרני טלפונים, צליל ורטט פיזיים, אתחול אמיתי ומכשירי API 26–35. הייבוא של גיבויי הגרסה המקורית אינו נתמך; האפליקציה המקורית נשארת בנפרד.

הכללים למדידת משכי זמן ולהרשאות נבדקו מול תיעוד Android: [SystemClock](https://developer.android.com/reference/android/os/SystemClock), [תזמון התראות](https://developer.android.com/develop/background-work/services/alarms), [בקשת הרשאות בהקשר](https://developer.android.com/training/permissions/requesting).

תוצאות הבדיקה והמסירה מתועדות ב־[DELIVERY-3.3.md](DELIVERY-3.3.md).
